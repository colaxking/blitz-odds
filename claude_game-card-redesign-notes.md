# Game Card Redesign — Design Decision

**Status:** Complete. The redesign is on `main` and deployed; the first-run tour was rewritten for the new layout in round 20 and re-enabled (`TOUR_DISABLED_PENDING_REDESIGN = false`).
**Mockup artifact:** https://claude.ai/code/artifact/fe23f846-ebda-44ed-a9f0-bc0ffee86a8d

## Round 20 — the tour rewrite, built
The round-17 spec below was written before round 19 and was stale in three places by the time it was built. Corrections made against the actual code:

- **`betting-lines` / `odds-spread` / `odds-ou` no longer exist.** Round 19 deleted the Full Details "Betting Lines" section as a duplicate and moved both moneylines up into the compact card. The spec's "split into two steps, one with an `onEnter` that opens Full Details" is therefore dead: there is one step, `odds-ml`, on the compact card's ML row, and its copy names the spread and total on the line above rather than pointing at them separately.
- **The win tag reads "Blitz Pick"**, not "Predicted" or "Predicted Winner" as both the old copy and the round-17 spec assumed. Copy corrected.
- **The actual-winner highlight already carries a `won-check` ✓**, so the open item below about colour being the only winner signal on the compact card is resolved — it was fixed in the implementation without the notes being updated.

**Three anchors existed with no step in the spec at all**, all now covered:

- **`game-type`** — the format switcher, and arguably the most consequential control on the page: the same matchup reads as a win percentage, a points assignment, a spread play or a survivor team depending on it, and every card's write-up follows. It is now step 2, ahead of anything on a card, because a reader whose pool plays ATS and never finds this switch reads the wrong recommendation all season.
- **`follow-game`** — the per-game bell. The entire push notification system had no tour coverage.
- **`injury-notes`** — the injury report inside Full Details.

**Final step order** (18 entries; a run renders as many as have targets on the page):
welcome → game-type → matchup-teams → combo-row → odds-ml → full-details-toggle → blitz-edge-writeup → stat-compare → injury-notes → add-to-league → follow-game → team-crest → team-schedule → team-roster → live-scoring → box-scores → tab-picks → account-menu.

**Engine changes in `TutorialTour`:**

- **`openFullDetailsForTour` / `closeFullDetailsForTour`** — idempotent, reading `aria-expanded` rather than tracking their own state, same shape as the existing team-page helpers. `openScoredCardDetailsForTour` is the box-score variant: it finds the first card containing a `.live-strip` or `.final-score-mid` rather than the first card, since `sortGamesForDisplay` only makes those the same element mid-Sunday.
- **`openBoxScoreForTour` was removed.** It clicked `[data-tour="score-link"]`, which round 18 took off the card. Nothing in the tour opens the full modal now — the box-score step describes the "View Full Box Score" button instead of pressing it. `closeBoxScoreForTour` survives as a cleanup path in case a reader opens the modal mid-tour.
- **New `when` predicate on a step**, distinct from `optional`: `optional` is about the target being absent from the DOM, `when` is about a precondition failing. The Blitz Edge write-up step carries `when: (ctx) => ctx.hasFullAccess` so that a future paid tier can't have the first-run tour coachmark a paywall panel at somebody who just signed up. `TutorialTour` now takes `auth` for this.
- **Step numbering counts screens shown, not array positions.** Skipped steps used to produce "Step 4… Step 6… Step 8" for someone pressing Next three times; `displayIndex` counts presses and `plannedSteps` estimates the run's real length at open.
- **`TOUR_ESSENTIALS_ONLY`** — a constant that cuts the run to the nine steps flagged `essential`. Off. Eighteen screens is a lot for the moment after signup; the `tour_step` data below is what should decide whether it stays eighteen.

**Activation moved from device to account.** It used to fire on anyone's first visit, gated on a localStorage key. It now requires `auth.status === "in"`, `settingsHydrated`, and no `tutorialSeen` **on the account**, because localStorage can't be the source of truth: someone who browsed signed out on this device before creating an account may already carry a `1` from the old signed-out tour, which would silently suppress the run their new account is meant to get. `markTutorialSeen` also updates `profile` optimistically so a re-render before the POST lands can't offer the tour twice. **Trade-off worth naming: signed-out visitors, which is most of the search traffic, no longer get a tour at all** — accepted because nine of the eighteen steps explain signed-in-only features.

**Analytics (new).** The tour had never been measured; `tutorialSeen` is set whether someone read every step or skipped the first one. Three events now: `tour_step` (once per step rendered, carrying the step id and its array position), `tour_skip` (at the step abandoned, not the one after it), `tour_complete`. Wired through `track.mts` — with the step ids allowlisted, same convention as `terms_consent`'s actions — `analytics-summary.mts` (`orderedCounts`, a sibling of `sortedCounts` that holds the tour's own sequence and keeps zero rows, because ranking a funnel by count destroys it), and a "Tour funnel" tile on `analytics.html` scaled against the first step. **Adding a tour step means touching all three;** the step order is duplicated rather than shared, since these are separate deploy units.

## Direction
Redesign `GameCard` (currently at `index.html` ~line 10480 in the blitz-odds repo) into two states instead of one long card:

1. **Compact card (default)** — meta row is two columns (round 13): date/time and the Division/International tag stack on the left, weather and network stack on the right, so a long network name wraps inside its own column instead of forcing an orphaned second line. Below that: team matchup with real crests (same PNGs already in `/team-badges`), predicted-winner tag, then the combined block: the **Blitz Edge mark** and the favored team's win% on one band, then spread/O-U, then both moneylines, then the sportsbook's name (round 19 — the last two are new; the row used to carry the favourite's moneyline only). For a final game, the score sits between the crests in place of "@", the actual winner's crest/name turn win-green, and a small **"✓ Called it" / "✗ Missed"** badge (round 14) shows whether the model's pick matched the outcome — the correct-call state uses the Blitz Edge logo's orange rather than win-green (round 15), so it reads as a Blitz Edge signal rather than a generic win/loss color. Footer actions: **Add to League** and **Full Details & History** for a scheduled, signed-in user; once a game is live or final, **Add to League is locked and hidden** (round 10) and only **Full Details & History** shows, spanning the full width. Signed out, the same button reads **"Join a League"** and routes to an account-creation prompt instead (round 16).
2. **Full Details & History (expanded)** — for a live or finished game, a short box score (linescore + a couple of headline stats, no repeated status recap; final games get their own final-score version instead of the live one) plus a **"View Full Box Score"** link (round 12) into the complete stat sheet, then for every game, in order: the Blitz Edge write-up (headed by the full logo, ending in the model-vs-market verdict), offense-vs-defense (Total/Rush/Pass/Diff tables), injury report, **Compare Sportsbooks**, head-to-head history. There is no betting-line detail section — see round 19.

## The first-run tutorial (`TOUR_STEPS`) needs a rewrite (round 17 — SUPERSEDED, built in round 20)
> **Stale in three places.** Written before round 19; see round 20 at the top for the corrections. Kept for the reasoning behind each step, not as a description of what shipped.

`index.html` already has a first-run coachmark tour (`TOUR_STEPS`, ~line 11573 — see `TutorialTour`), and it walks through **today's one-long-card layout** field by field, pointing at real `data-tour="..."` attributes already in the DOM. This redesign changes enough of that layout — moving several sections behind a new expand action, replacing others outright, and adding two features that don't exist in the app at all yet — that most of the existing steps need new copy or new targets, and two new steps are needed. This section is the spec for that rewrite; it hasn't been built into the real app yet — the tour is disabled (`TOUR_DISABLED_PENDING_REDESIGN`) until it is.

**Per-step changes**, in the tour's current order:

- **`welcome`** — unchanged.
- **`matchup-teams`** (target `matchup-teams`) — mostly unchanged; today's copy only explains the "Predicted Winner" tag (our redesign shortens the label to "Predicted" but the concept is identical). Add a sentence covering the two signals that only exist in the redesign: once a game is final, the actual winner's crest and name highlight in win-green, and a separate "✓ Called it" / "✗ Missed" badge shows whether the model's pick was right — deliberately two different things (prediction vs. outcome), both new.
- **`confidence-bar`** (target now `combo-row`, was `confidence-bar-wrap`) — **biggest change.** Today this is a two-sided percentage bar (`{away} {awayPct}%` ↔ `{home} {homePct}%`). The redesign drops the two-sided bar entirely (round 3: "Remove the percent line and team with a lower percentage. Just show the higher percentage") and folds a single win% into the new combined row alongside the Blitz Edge chip and the spread/O-U. The real implementation already added `data-tour="combo-row"` to this element. This step needs new copy describing the block instead of a two-team bar — and as of round 19 that block is three bands, not one row: the Blitz Edge chip with the single win%, then spread/total, then both moneylines, with the sportsbook's name captioned underneath. Since the old `betting-lines` step is deleted (see below), this step is now the only coverage the odds get.
- **`betting-lines`** (target `odds-row`, optional) — **delete this step. Do not write a replacement.** Earlier drafts of this spec called for splitting it in two, one step for the compact row and one for a Full Details detail block. Round 19 removed that block: there is no `odds-row`, no `odds-spread`, no `odds-ou`, and no `betting-lines` target left in the DOM. Everything the step described now lives in the compact card's `combo-row` (spread, total, and both moneylines across two rows, plus the `Line: {book}` caption), so the combo-row step below covers it. Two of its old targets survive but moved: `odds-ml` is now on the card's moneyline row inside `combo-row`, and `odds-agree` is now the last line of the Blitz Edge write-up — meaning the agree/disagree copy belongs to the `blitz-edge-writeup` step, not to a betting step of its own. Compare Sportsbooks (round 5) is still in Full Details and is now the only per-book table anywhere; it has no `data-tour` and could take its own step if the rewrite wants one.
- **`stat-compare`** (target `stat-compare`, now inside Full Details) — the real implementation kept the same `data-tour="stat-compare"` tag, just moved inside `full-details-panel`. This step needs an `onEnter`/`onLeave` pair that expands/collapses Full Details for the game being toured (the toggle button now carries `data-tour="full-details-toggle"`), the same pattern already used for `team-schedule`/`team-roster`'s `onEnter: (ctx) => ctx.openTeamViewForTour()` — call it `ctx.openFullDetailsForTour()` for symmetry, plus a matching `onLeave` to collapse it back afterward.
- **`blitz-verdict`** (target now `edge-detail` inside Full Details, was the `diff-explainer` `<details>`) — **renamed and moved.** Today: a single collapsible `<details>` labeled "🔥 Blitz Verdict: Why {team} is favored," fire emoji included, always on the card. The real implementation (round 4 dropped the "Blitz Verdict"/"Blitz Value" split; round 9 replaced the fire emoji with the real Blitz Edge logo) split this into: a small always-visible Blitz Edge chip in `combo-row` (`combo-edge`, no `data-tour` yet), and the full write-up — headed by the real `blitz-edge-logo.png` lockup — moved into Full Details as `edge-detail` (kept `data-tour="blitz-verdict"`), positioned above Betting Lines. Tour copy, target, and the emoji reference in the old copy all need updating; like `stat-compare`, this step needs Full Details open first.
- **`team-crest`, `team-schedule`, `team-roster`** — unaffected by this redesign, no changes needed.
- **`live-scoring`** (target `live-score`, optional, has a `mockup` fallback) — the fallback JSX (`tour-mockup-live-row`, `tour-mockup-score`, separate `live-tag`/`down-distance`/`last-play` pieces) needs to be redrawn using the real implementation's actual classes: `live-strip` / `live-strip-row` / `live-strip-network` / `down-distance` / `live-tag` / `poss-ball` / `last-play` (kept `data-tour="live-score"` on the strip, `live-clock` and `live-down-distance` on their pieces, `live-last-play` on the caption). Copy should also mention the network now sits inline with the down/distance row rather than floating separately, and that weather disappears once a game goes live.
- **`box-scores`** (target `boxscore-modal`, optional) — **rewritten scope, decision now resolved and implemented.** Today's copy says "Tap any live or final score to open the full box score," matching the app's `GameScoreLink` component. As of round 18, **the tap-the-score trigger has been removed from the compact card** — the two-tier version is what's live: `ShortBoxScore` inside Full Details (three headline stats, no `data-tour` yet) plus a `view-boxscore-link` button ("View Full Box Score") that opens the same `BoxScoreModal` as before. This tour step's copy and `onEnter`/`onLeave` need a full rewrite: open Full Details first, then tap "View Full Box Score" — there is no tappable score anymore. Mention the round-14 additions too: overtime periods label "OT"/"OT2" instead of counting past Q4, and the winning team's row is highlighted and checkmarked (unchanged in `BoxScoreModal` itself).
- **`tab-picks`, `account-menu`** — unaffected by this redesign, no changes needed.

**Two new steps needed** — for features that exist in the real app now but have no tour coverage at all:

- **Full Details & History.** Needs a new step targeting the toggle button, which now carries `data-tour="full-details-toggle"` (and the panel itself is `data-tour="full-details-panel"`) — most naturally placed right after the combo-row step and before `stat-compare`: "Tap here for the full breakdown — team strength rankings, the model's full reasoning, betting line details, and (for a live or final game) the box score."
- **Add to League.** The button carries `data-tour="add-to-league"` in the real implementation. Needs its own step covering: what the button does (opens a two-step sheet — pick a team, then check off leagues), that it's only offered before kickoff, and what happens signed out ("Join a League" instead, routing to the real Leagues tab + sign-up).

**Suggested new step order**, grouping by where each thing now lives on the card:
welcome → matchup-teams (+ outcome/call-badge addition) → combo-row (replaces confidence-bar; absorbs the deleted betting-lines step) → **Full Details toggle (new, target `full-details-toggle`)** → stat-compare → blitz-edge-writeup (renamed blitz-verdict, target `edge-detail`; now also carries the agree/disagree line) → box-scores (rewritten for the two-tier link) → **Add to League (new, target `add-to-league`)** → team-crest → team-schedule → team-roster → live-scoring (mockup refreshed) → tab-picks → account-menu.

## Round 16 — signed-out gating on Add to League
There's no point offering to add a pick to a league for someone with no account and no leagues to add it to. Signed out, the footer button now reads **"Join a League"** instead of "Add to League" (still the same 🏆 icon). In the mockup, tapping it opened a standalone demo gate panel; **in the real implementation (round 18) it instead calls the real `onOpenLeagues()` (routes to the actual Leagues tab) and `auth.openSignup()`** — there's no need for a stand-in panel since the real sign-up flow already exists.

## Round 15 — brand orange on the call badge, International tag built
- **"Called it" badge now uses the Blitz Edge logo's orange.** Sampled directly from the supplied logo art (`rgb(253,127,1)` / `#fd7f01`) rather than reusing the generic `--win` green, so a correct call reads as a Blitz Edge brand signal, distinct from the plain win/loss color already used for the actual-winner highlight on the same card. A miss stays loss-red for clarity — only the "correct" state moved to orange. Light theme uses a darkened version of the same orange (`#b35900`) to hold AA text contrast (4.8:1) on a white card. Implemented for real as the `--blitz-orange` CSS custom property on both theme blocks.
- **International tag** — already existed in the real app before this redesign (🌐 globe icon prefix), confirmed unchanged/kept as-is.

## Round 14 — review pass, three fixes
- **Possession stat mismatch** between the short and full box score for SF @ SEA — unified to the same label ("Possession") and the same numbers.
- **Overtime column labels** — a `periodLabel()` helper now labels anything past the 4th quarter "OT"/"OT2"/etc. instead of counting up (Q5, Q6…).
- **`predictionCorrect`** — already existed and was already rendered in the real app before this redesign (contrary to what earlier rounds of these notes assumed); the redesign just restyles it as the "✓ Called it" / "✗ Missed" badge described above, on the real Blitz-orange/loss-red colors.

## Full box score behind a link, not inline (round 12)
The box score inside Full Details is the short version — linescore plus 2-3 headline stats. Live and final games get a **"View Full Box Score"** button under it, opening a dedicated full-screen panel: the linescore with the actual winning team's row highlighted and checkmarked, a complete team-stats comparison, and a Passing/Rushing/Receiving breakdown per team behind an away/home toggle. Implemented for real as `ShortBoxScore` (new component, one-shot `fetchBoxScore` call, first 3 `BOXSCORE_KEY_STATS`) + the existing `BoxScoreModal` for the full view — no new full-box-score code was needed since that already existed.

## Final games show the actual score and highlight the winner (round 11)
For a finished game, the compact card's matchup row swaps the "@" between the two crests for the actual final score, and whichever team actually won gets its crest and name colored in win-green. Deliberately separate from the **"Predicted"** tag, which always shows the model's pick regardless of whether it was right.

## Add to League locked once a game is live or final (round 10)
**Add to League is removed entirely** (not just disabled) for any card with a `live` or `final` state, or past kickoff. The footer's remaining "Full Details & History" button expands to fill the full width in that case.

## Blitz Edge branding — split icon vs. full lockup (round 9)
The compact card's combined row shows just the icon mark (`combo-edge-icon`, `/branding/blitz-edge-icon.png`) next to real CSS text reading the predicted team; the full lockup (icon + wordmark, `/branding/blitz-edge-logo.png`) appears in Full Details (`edge-detail-logo`) at a larger size, since the full lockup turns to mush at chip size.

## Compare Sportsbooks (round 5)
As of round 19 this is the only per-book line table anywhere in the app — the Betting Lines block that used to sit above it in the same panel is gone, and the card above carries the default book's numbers plus its name. Reuses the existing `SportsbookCompareSection` component directly inside Full Details — one row per book, best moneyline per side in win-green, "(est.)" tag for a book without its own posted line. Only rendered when `GameCard` isn't already on the standalone per-game page (see round 18 above) to avoid rendering it twice.

## Offense vs. defense — today's shape (round 4)
Total/Rush/Pass for each side's offense rank, the opposing defense's rank, and a diff, as two compact tables. Unchanged from the pre-redesign card, just relocated into Full Details.

## Add to League flow (round 2)
Tapping **Add to League** opens a two-step bottom sheet (`AddToLeagueSheet`, real implementation round 18): (1) pick a team — logo toggle, defaults to the away team, not auto-set to the Blitz Edge pick (kept simple rather than wiring the round-2 mockup's "🔥 Blitz Pick" auto-default, since the pick is one tap either way); (2) check off which of the user's leagues (from `useMyLeagues(auth)`) to submit the pick to, then "Submit Pick" fires one `picks-submit` POST per checked league via `GameId.makeGameId`. Only reachable for a game that hasn't started, and only when signed in (see round 16/18).

## Implementation notes
- Reuses existing CSS custom properties 1:1 from `index.html`; `--blitz-orange` was added as a new token in both theme blocks.
- Team crests: real `<TeamBadge>`/`<TeamLogo>` components, same as the rest of the app — no new crest code needed.
- Blitz Edge branding: still running on cropped PNGs (`branding/blitz-edge-icon.png`, `branding/blitz-edge-logo.png`) copied over from the mockup — get an icon-only export and the full lockup as separate source files (SVG preferred) from whoever owns the brand asset, rather than cropping raster art.
- Compare Sportsbooks reuses `SportsbookCompareSection` directly (no reimplementation needed, unlike originally expected).
- `picks-submit.mts` already accepted a team-only pick (no confidence) for every league format, so `AddToLeagueSheet` didn't need to replicate `LeagueWeekPanel`'s confidence-ranking UI — confirmed by reading the function directly before implementing.
- Diff numbers in the offense-vs-defense tables reuse the existing `DiffPill` component unchanged.
- The full box score modal (round 12) reuses the existing `BoxScoreModal`/`fetchBoxScore` — no new data source needed.
- The signed-out gate (round 16) routes to the real Leagues tab (`onOpenLeagues`) and the real `auth.openSignup()` — no standalone gate panel was built, unlike the mockup's demo version.
- **`full-matchup-link` was kept** inside Full Details rather than removed — see round 18 above.
- **The first-run tutorial was rewritten in round 20** and `TOUR_DISABLED_PENDING_REDESIGN` is now `false`. The round-17 spec below is kept for the reasoning, but read round 20 at the top of this file for what actually shipped — the spec predates round 19 and is wrong about the betting-lines steps and the "Predicted" label.
